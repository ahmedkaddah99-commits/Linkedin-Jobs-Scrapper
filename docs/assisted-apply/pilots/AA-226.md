## 2026-08-02 live-defect remediation addendum

A user-authorized, non-submitting Lever run exposed four reproducible defects before
any field mutation: the immutable package froze the job-details URL instead of the
provider's application-form URL; the extension included the browser-only `reviewId`
in a durable backend report; selected package documents were not dispatched by the
preparation coordinator; and legacy ready workspace CV records were excluded by the
frontend picker even though the backend safely supports them.

The bounded remediation now:

- freezes a Lever package URL at its deterministic `/apply` form route before package creation;
- sends only backend-accepted sanitized progress keys;
- fills and verifies package fields, then obtains a fresh grant and verifies each selected upload on the exact inactive owned tab;
- admits only ready legacy `workspace_cv` assets with a supported PDF/DOCX MIME type, while rejecting an explicitly unsupported MIME type;
- keeps all terminal submission and navigation pathways structurally guarded.

Sanitized fixture regression evidence: the complete Chromium extension suite passed
23/23. The added orchestration case filled three supported Lever fields and attached
one verified PDF while inactive, persisted deterministic completion, activated only
the exact owned tab for review, and observed zero submit events, `requestSubmit`,
`form.submit`, Enter submissions, terminal clicks/requests, success transitions, or
final navigation.

This remediation does not convert AA-226 to PASS. The required 10-form live sample
still has not been completed and broad production enablement remains unauthorized.
