# RC-010 first acquisition-to-user slice

This fixture proof follows one dual-ready employer through the existing source
observation contract, SQLite ingestion, staging publication, public head, and
the authenticated `GET /v1/personalized-jobs` route used by the frontend
`/jobs` page.

## Evidence test

`tests/test_rc010_first_acquisition_slice.py::test_rc010_dual_source_slice_reaches_jobs_and_preserves_public_head_on_failure`

The test records these bounded facts:

- one employer observation and one LinkedIn observation share the fixture
  canonical company ID and deduplicate to one canonical job;
- both source observations remain durable with their source-specific ATS
  values and full observation contract in raw evidence;
- staging is promoted to one valid public job;
- two authenticated user Jobs reads return that same job without increasing
  `acquisition_requests`;
- replaying both completed inputs leaves one canonical job, two source
  observations, and the same canonical-company count;
- an invalid LinkedIn final delivery marks that source `unknown` and the task
  `failed`, while the employer result and prior public publication remain
  available.

The fixture uses source target IDs `acme-employer` and `acme-linkedin`; task
IDs are generated by the SQLite store for each isolated cycle and are asserted
through the cycle read model. No runtime-generated task IDs or screenshots are
claimed until the verification command is executed.

## Verification command

From the repository root, after restoring the required project virtual
environment:

```powershell
.venv\Scripts\python.exe --version
.venv\Scripts\python.exe -m pytest tests/test_rc010_first_acquisition_slice.py
```

No live provider, browser, network, bulk catalog, or VPS operation is part of
this proof. Browser screenshots remain a staging walkthrough follow-up because
the current worktree does not contain the required `.venv` interpreter and no
local frontend server was started.
